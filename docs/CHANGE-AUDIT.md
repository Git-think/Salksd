## 已撤回的过度改动

| 位置 | 问题 | 修正 |
|---|---|---|
| `secure_show_links()`、HTTP rewrite | 将 `/sub/...` 专用路径变成默认入口 | 默认订阅恢复为原 `https://域名/原token`；原 token 不变，移除新增 `/sub/` 路由 |
| `secure_publish()`、HTTP 路由 | 把五个节点拆成每客户端多条订阅和单节点地址 | 一个原订阅 URL 按客户端分流；每份内容为 VLESS、TUIC 安全/兼容、HY2 安全/兼容，共五节点 |
| HTTP 普通订阅输出 | URI 列表直接明文下发 | 普通 URI 订阅恢复整体 Base64；用户已明确同意 Clash/sing-box 原生 YAML/JSON 例外 |
| `download_unbound_binary()` | 下载超时从原 10 秒增至 60 秒，没有任务必要性 | 恢复 10 秒；仅保留 `-f` 及失败返回，避免重启事务把 HTTP 错误页当二进制 |

旧客户端若不支持 `v2rayn://` 原生节点，会忽略带 PEM 的两条节点，仍可用同一订阅中的三个标准 URI 节点。不能声称所有旧客户端都会显示五个节点。NekoBox 用其实际支持的原生 sing-box JSON，以保留 PEM；这不是整体 Base64 JSON，因为其旧版解码后仅尝试 URI 解析。

## SNI 选择修正（不替换已发布证书）

原 TUIC/HY2 分享链接使用 `www.bing.com`。此前兼容节点继承了站点域名 SNI，属于不必要改动；本轮已恢复原值。新安装/旧版首次迁移也默认保留原 SNI，在新自签名证书里加入相应 SAN。现有有效持久证书及已经保存的 TLS_SERVER_NAME 继续复用；测试服务器已发布的 API 域名证书不更换，安全节点继续匹配其 SAN。网站 HTTPS 证书和代理自签名证书用途不同，不要求同名。

## 限时分享追加检查

分享随机数输出先逐项检查，完整账号文件通过校验后才原子替换；失败不破坏既有账号。撤销提交后先结束旧核心，再做证书/下载/配置处理，避免后续失败使撤销账号继续运行。恢复服务时始终重新过滤到期/撤销账号。仅有有效分享时启动现有保活脚本的期限守护模式，检查具体 PID、进程启动时间和本代标识，避免误杀替换后的进程。

本地实际核心验证了独立账号撤销，三 IP 诊断和本轮部署结果见 TEST-RESULTS.md。用户要求的“非代理访问返回宣传页”采用明确的客户端 User-Agent 白名单；它可以被仿冒，不作为账号授权依据。

本轮实机结论：重启后身份未变；两份独立分享的主动撤销/自然到期及旧节点失效、自用保持可用均已验证。Serv00 隐藏配置和私有数据目录的前置 403 无法由 PHP 伪装，已保留访问权限并列入限制。
