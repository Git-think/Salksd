## 测试中发现并修复的问题

1. `ps -u` 在 FreeBSD 含义不同；改用 `ps -U`。随后实测发现 `-o pid=,args=` 在 FreeBSD 被解析成一个输出字段，改为 `-o pid= -o args=`，新增回归检查。
2. 上述查询错误导致旧保活未退出，多次测试后触及平台进程限额。已保存进程清单并清理确认属于本服务的重复保活；正常重启还会清理其 sleep 子进程，启动前防止再开第二个保活。最终验证为一个核心和一个本服务保活。
3. PHP 网站进程受 `open_basedir` 限制，不能读取 `~/.config`。将客户端订阅发布副本置于站内受保护目录，服务器私钥保持站外。
4. Serv00 前端无法执行权限 600 的入口 PHP，实测同一无敏感数据的测试 PHP 在 600 时返回 404、644 时返回 200。最终使用不含秘密的 644 入口，700 数据目录和 600 数据文件，并增加 `.htaccess` 拒绝 HTTP 直读。HTTPS 全流程复测通过。
5. 旧订阅 token 的 sed 正则在平台上没有取出原规则，导致保存了错误的地址；原规则和 PHP 未被删除。改为 awk 解析并以原规则为准，新增旧 token 与错误状态恢复的回归检查，保持原 URL。
6. 早期恢复测试备份时使用 077 umask 且未给 tar 加 `-p`，使原 PHP/首页权限变成 600。已按首次备份恢复其原始权限，保留原内容，并把保留权限要求加入回滚步骤；不把此问题掩盖为原脚本错误。
7. 2026-11-20 新网页流程首次测试：任务子进程继承保活命令行，被进程筛选误认为旧保活，导致任务在变更端口前被终止。面板显示失败，原端口和核心仍运行。修正为保活内部任务保留本保活及子进程，只停止核心；新增离线回归检查，修正后全端口及单 TUIC 网页操作均通过，见上表。
